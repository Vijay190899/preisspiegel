# Decision Log

Short ADRs. Newest at the bottom. Format: **Decision**, then _why_, then _alternatives_.

1. **A synthetic tender with a fictional contractor and fictional suppliers.** _Why:_ real supplier offers are not public, and a generator gives ground truth, which is what makes the benchmarks possible. Nothing can be mistaken for a real company's data. _Alt:_ a real public tender (no supplier offers and no ground truth to score against).
2. **The model proposes, code decides.** _Why:_ trust. The model reads text and returns typed attributes with verbatim quotes; code verifies the quotes and runs the checks that decide accept or flag. _Alt:_ letting the model judge the match end to end (unverifiable, and it fails silently).
3. **LLMs never originate numbers.** _Why:_ a price an estimator signs for must come from a document. Prices, quantities and totals are parsed by code, and a number guard confirms each displayed value sits inside its cited region. _Alt:_ model-extracted figures (a transposed digit looks exactly like a correct one).
4. **Cheap by default: Haiku 5.5 does all bulk work, escalation is off, every role is an env var.** _Why:_ cost per tender is a product number. The estimate is about $0.45 for a 1,170-position tender (B1 will replace it with a measurement). A larger model is switched on only where a benchmark (B4) shows it earns its cost. _Alt:_ a larger model everywhere (simpler; Sonnet 5.5 costs 20 times as much per token and Opus 5.5 costs 40 times as much).
5. **OpenRouter by default, Anthropic direct as a switch (`LLM_PROVIDER`). One code path: the official `@anthropic-ai/sdk` against either endpoint.** _Why:_ one key, the same per-token prices, and model flexibility for comparison runs. _Trade-offs:_ a credit fee of about 5.5%, reported separately; features are confirmed per provider by `pnpm probe:llm` and switched off with `LLM_CAPS_OFF`. _Alt:_ an OpenAI-compatible client (a second code path that loses Anthropic-native features).
6. **A hand-written agent runtime on Convex: an append-only event log plus scheduler-driven batches.** _Why:_ the pipeline is a batch over positions, not a chat. The event log is the product surface (live progress, replay, cost per step), so it should be ours to shape. _Alt:_ `@convex-dev/agent` (built around conversation threads), an external agent framework (state outside the database the UI subscribes to).
7. **Workspace layout: `apps/web`, `services/backend`, `packages/core`, `data`, `bench`, with root `package.json` scripts as the only task runner.** _Why:_ the Convex backend is its own package that the web app imports types from; pure logic lives in one place and is shared by the backend, the benchmarks and the generator. _Alt:_ the template's single app with `convex/` inside it (simpler, but logic ends up duplicated between the app and the scripts).
8. **`llm/registry.ts` is pure and takes the environment as a parameter.** _Why:_ the same module runs inside Convex (typed `env`) and in Node scripts (`process.env`), and it is unit-tested without either. Convex code never reads `process.env`. _Alt:_ reading the environment inside the registry (untestable, and two copies).
9. **The ledger is one row per model call plus a running total per day.** _Why:_ the budget guard runs before every call and should read one document, not sum a table. Both are written in the same mutation. _Alt:_ summing the ledger (grows with every run), the aggregate component (more machinery than one counter needs).
10. **Development uses a local Convex deployment with no account; a cloud deployment is linked at M4.** _Why:_ nothing in M0–M3 needs the cloud, and setup takes no sign-in. _Alt:_ a cloud dev deployment from the start.
11. **Theme switching is an inline boot script plus a `useSyncExternalStore` hook; the locale works the same way.** _Why:_ no flash of the wrong theme, no dependency, and correct server rendering. German is rendered on the server and the client switches if English was chosen. _Alt:_ a theme library; a cookie-based locale (needs server code for a toggle).
12. **`@tanstack/react-router-ssr-query` replaces the template's `@tanstack/react-router-with-query`.** _Why:_ the template's package fails against the current router (`router.serverSsr.isDehydrated is not a function`); this is the integration the Convex quickstart now documents. _Alt:_ pinning the router to an old version.
13. **Dependency build scripts are allowed for `esbuild` only.** _Why:_ pnpm blocks install scripts by default; `esbuild` needs its own to place the platform binary. Everything else stays blocked. pnpm also added a release-age exception for `@anthropic-ai/sdk@1.9.0` to `pnpm-workspace.yaml`: that version was published on 2026-11-16, the day it was installed. _Amended 2026-11-17:_ the SDK is pinned to `^1.8.0`, which resolves to 1.8.0, and the exception is removed. The lockfile passes pnpm's release-age policy with no exceptions.
14. **shadcn/ui is deferred from M0 to M3.** _Why:_ the shell needs no components from it, and adding it when the first table and dialog are built keeps its variables mapped onto our tokens in one step. _Deviation from the plan,_ which listed it under M0.
15. **The seed is loaded with `convex import`, as rows parsed by the real readers. Rows refer to their tender by slug, not by document id.** _Why:_ the import is authenticated by the CLI, takes files of any size, and validates every row against the schema, so there is no public write endpoint to protect. A slug survives a reload; document ids do not. _Alt:_ a token-guarded HTTP endpoint (more code and a secret to manage), an internal mutation called through `convex run` (argument size limits).
16. **PDF text is extracted outside Convex, and the table reader is pure code in `packages/core`.** _Why:_ pdf.js runs in Node and in the browser without being bundled into a Convex function, and a reader that takes text with positions and returns lines with rectangles can be tested without a PDF. Columns are found from the table's own header row, with no model involved. _Alt:_ extracting inside a Convex action (bundling pdf.js there), a model reading the layout (cost on every document, and a number it reads is a number it originated).
17. **The ground truth is a file the benchmarks read. It is never loaded into the database.** _Why:_ the pipeline cannot see what it is scored against, by construction. _Alt:_ a truth table in Convex (convenient for a debug view, one query away from leaking into a prompt).
18. **Sixty traps in total (3.8% of the wholesaler's lines, 7.5% of the specialist's, 0.9% of the GAEB offer's), and the split that follows is stated as chosen.** _Why:_ the specialist's lines each answer several positions, so the same density there would flag far more positions than is plausible. The resulting 90.8% expected to price automatically is a property of this tender, and DATA.md says so. _Alt:_ tuning traps until a round number appears (a benchmark built to produce its own headline).
19. **The catalogue has 254 products, not the roughly 300 the plan named, and names were replaced after a search.** _Why:_ 254 is what the product families produce without padding. The contractor, the specialist supplier and the data brand first had names too close to real businesses and were renamed before the first commit. _Deviation from the plan._
20. **Design direction "Planblatt": the app is a drawing sheet on a drafting table.** _Why:_ the people this is for read plans all day, so the interface borrows from one: a title block for the tender, square-cornered sheets with crop marks over a drafting grid, condensed capitals for field labels, and a checker's marks for what needs a decision. Light is plan paper, dark is a blueprint, copper is the one accent. It also keeps the product from looking like every other dashboard. _Alt:_ a neutral card layout (the M0 shell, replaced), or the warm "command center" look of an earlier project (not this domain).
21. **Components are built by hand on the tokens; shadcn/ui is not used.** _Why:_ the direction in ADR-20 needs square sheets, ruled grids and lettered labels, and restyling a component library to that costs more than the few primitives the app needs. _Amends ADR-14,_ which deferred shadcn/ui to M3. _Alt:_ shadcn/ui with its variables mapped onto the tokens.
22. **Status colours are validated, and blue sits between green and red.** _Why:_ approved (green), settled by the system (blue) and open (red) appear side by side in one bar. In that order every neighbouring pair passes the colour-blindness check of the dataviz validator against both sheet colours; green beside red does not. _Alt:_ green next to red with labels as the only safeguard.
23. **An independent audit closes every milestone.** _Why:_ the builder's own gate report cannot see its own blind spots. A fresh agent with no part in the work re-runs the gate in a clean checkout, recounts every number in the docs, checks the non-negotiables by search, and ranks what to tighten. High-severity findings are fixed before the gate is reported; the rest are listed in HANDOVER. _Alt:_ self-review only.
24. **The model call path uses `messages.create` and reads the answer itself.** _Why:_ found by the first audit. The SDK's `messages.parse` raises when the text does not fit the schema, which is what a response cut off at `max_tokens` looks like, and the raise skipped the ledger write for a billed call. `readStructured` turns every outcome into a value, the ledger row is written first, and a role can no longer name a model without a price. _Alt:_ catching the SDK's error (the usage is gone by then).
25. **Deviations the first audit found, logged after the fact.** M1 was built before the M0 gate closed, because the provider key arrived later and M1 needs no model. Ledger rows had no run id until the audit; they have one now. Pack units appear only on trapped lines, against the plan's call for messy clean lines; that is the first M2 task. The catalogue has 29 groups where the plan spoke of about 12 classes. `pnpm demo:reset` does not exist yet and arrives with replay mode.
26. **Design direction "Schaltplan" replaces "Planblatt".** _Why:_ the owner judged the drawing-sheet interface plain and crowded. The new one takes its form from what an electrician reads and builds: the tender is drawn as a single-line diagram (offers feed a busbar, titles go out as feeders), surfaces are modules on a mounting plate, status is shown by pilot lamps, and copper marks only what is energised or is the next thing to do. One view holds one headline, one sentence and one action; detail opens on request. One sequence of motion switches the diagram on; all other motion answers an action. _Supersedes ADR-20;_ ADR-21 (built by hand, no component library) stands. _Alt:_ polishing the sheet layout (it would have stayed a page of ruled boxes).
27. **The interface is built alongside the pipeline, not after it.** _Why:_ the owner asked for it side by side, and a flag is easier to judge on screen than in a JSON file. _Deviation from the plan,_ which put the whole product surface in M3.
28. **The list of positions is TanStack Virtual with hand-built rows, not TanStack Table.** _Why:_ it is one column of rows under headings, not a grid with sortable columns. _Deviation from the plan,_ which named TanStack Table; the review queue may still use it.
29. **Runtime dependencies added to the web app:** `motion` (layout and sequence animation), `@number-flow/react` (counting figures), `pdfjs-dist` (the source page), `@tanstack/react-virtual`, `lucide-react`, and Archivo and IBM Plex Mono through Fontsource. _Why:_ each replaces code that would otherwise be written by hand and tested less. pdf.js is loaded on first use and stays out of the first page's bundle.
30. **A behaviour probe and a contrast test join the gate.** _Why:_ the second audit found `pnpm shots` passing with six defects live: a list of 1,170 Tab stops in front of the numbers, a crash on a hand-typed search value, a price per ring of cable labelled per metre, the palette reopening on Enter. A screenshot cannot see any of them. `pnpm probe:ui` drives the app and checks them; `tokens.test.ts` checks the contrast of every colour pair in use, which also makes ADR-22 re-verifiable. _Alt:_ more screenshots.
31. **While a source is open, the list gives its room to the document.** _Why:_ a list, a position and a legible page do not fit side by side at 1440 px; in the earlier three-column layout the table text of a PDF was 4 to 5 px tall. Now position and document share the screen equally, the page is never drawn narrower than 640 px, and it opens scrolled to the mark. From 1800 px the list stays. J and K still step through the list while it is away. _Alt:_ zoom and pan inside a narrow pane, or a modal over the position (which hides the number that was clicked).
