# Decision Log

Short ADRs. Newest at the bottom. Format: **Decision**, then _why_, then _alternatives_.

1. **A synthetic tender with a fictional contractor and fictional suppliers.** _Why:_ real supplier offers are not public, and a generator gives ground truth, which is what makes the benchmarks possible. Nothing can be mistaken for a real company's data. _Alt:_ a real public tender (no supplier offers and no ground truth to score against).
2. **The model proposes, code decides.** _Why:_ trust. The model reads text and returns typed attributes with verbatim quotes; code verifies the quotes and runs the checks that decide accept or flag. _Alt:_ letting the model judge the match end to end (unverifiable, and it fails silently).
3. **LLMs never originate numbers.** _Why:_ a price an estimator signs for must come from a document. Prices, quantities and totals are parsed by code, and a number guard confirms each displayed value sits inside its cited region. _Alt:_ model-extracted figures (a transposed digit looks exactly like a correct one).
4. **Cheap by default: Haiku 5.5 does all bulk work, escalation is off, every role is an env var.** _Why:_ cost per tender is a product number. The estimate is about $0.45 for a 1,170-position tender (B1 will replace it with a measurement). A larger model is switched on only where a benchmark (B4) shows it earns its cost. _Alt:_ a larger model everywhere (simpler; Sonnet 5.5 costs 20 times as much per token and Opus 5.5 costs 40 times as much).
5. **OpenRouter by default, Anthropic direct as a switch (`LLM_PROVIDER`). One code path: the official `@anthropic-ai/sdk` against either endpoint.** _Why:_ one key, the same per-token prices, and model flexibility for comparison runs. _Trade-offs:_ a credit fee of about 5.5%, reported separately; features are confirmed per provider by `pnpm probe:llm` and switched off with `LLM_CAPS_OFF`. _Alt:_ an OpenAI-compatible client (a second code path that loses Anthropic-native features).
6. **A hand-written agent runtime on Convex: an append-only event log plus scheduler-driven batches.** _Why:_ the pipeline is a batch over positions, not a chat. The event log is the product surface (live progress, replay, cost per step), so it should be ours to shape. _Alt:_ `@convex-dev/agent` (built around conversation threads), an external agent framework (state outside the database the UI subscribes to).
7. **Workspace layout: `apps/web`, `services/backend`, `packages/core`, `data`, `bench`, with root `package.json` scripts as the only task runner.** _Why:_ the Convex backend is its own package that the web app imports types from; pure logic lives in one place and is shared by the backend, the benchmarks and the generator. _Alt:_ the template's single app with `convex/` inside it (simpler, but logic ends up duplicated between the app and the scripts).
8. **`llm/registry.ts` is pure and takes the environment as a parameter.** _Why:_ the same module runs inside Convex (typed `env`) and in Node scripts (`process.env`), and it is unit-tested without either. Convex code never reads `process.env`. _Alt:_ reading the environment inside the registry (untestable, and two copies).
9. **The ledger is one row per model call plus a running total per day.** _Why:_ the budget guard runs before every call and should read one document, not sum a table. Both are written in the same mutation. _Alt:_ summing the ledger (grows with every run), the aggregate component (more machinery than one counter needs).
10. **Development uses a local Convex deployment with no account; a cloud deployment is linked at M4.** _Why:_ nothing in M0–M3 needs the cloud, and setup takes no sign-in. _Alt:_ a cloud dev deployment from the start.
11. **Theme switching is an inline boot script plus a `useSyncExternalStore` hook; the locale works the same way.** _Why:_ no flash of the wrong theme, no dependency, and correct server rendering. German is rendered on the server and the client switches if English was chosen. _Alt:_ a theme library; a cookie-based locale (needs server code for a toggle).
12. **`@tanstack/react-router-ssr-query` replaces the template's `@tanstack/react-router-with-query`.** _Why:_ the template's package fails against the current router (`router.serverSsr.isDehydrated is not a function`); this is the integration the Convex quickstart now documents. _Alt:_ pinning the router to an old version.
13. **Dependency build scripts are allowed for `esbuild` only.** _Why:_ pnpm blocks install scripts by default; `esbuild` needs its own to place the platform binary. Everything else stays blocked. pnpm also added a release-age exception for `@anthropic-ai/sdk@1.9.0` to `pnpm-workspace.yaml`: that version was published on 2026-11-16, the day it was installed. _Amended 2026-11-17:_ the SDK is pinned to `^1.8.0`, which resolves to 1.8.0, and the exception is removed. The lockfile passes pnpm's release-age policy with no exceptions.
14. **shadcn/ui is deferred from M0 to M3.** _Why:_ the shell needs no components from it, and adding it when the first table and dialog are built keeps its variables mapped onto our tokens in one step. _Deviation from the plan,_ which listed it under M0.
15. **The seed is loaded with `convex import`, as rows parsed by the real readers. Rows refer to their tender by slug, not by document id.** _Why:_ the import is authenticated by the CLI, takes files of any size, and validates every row against the schema, so there is no public write endpoint to protect. A slug survives a reload; document ids do not. _Alt:_ a token-guarded HTTP endpoint (more code and a secret to manage), an internal mutation called through `convex run` (argument size limits).
16. **PDF text is extracted outside Convex, and the table reader is pure code in `packages/core`.** _Why:_ pdf.js runs in Node and in the browser without being bundled into a Convex function, and a reader that takes text with positions and returns lines with rectangles can be tested without a PDF. Columns are found from the table's own header row, with no model involved. _Alt:_ extracting inside a Convex action (bundling pdf.js there), a model reading the layout (cost on every document, and a number it reads is a number it originated).
17. **The ground truth is a file the benchmarks read. It is never loaded into the database.** _Why:_ the pipeline cannot see what it is scored against, by construction. _Alt:_ a truth table in Convex (convenient for a debug view, one query away from leaking into a prompt).
18. **Sixty traps in total (3.8% of the wholesaler's lines, 7.5% of the specialist's, 0.9% of the GAEB offer's), and the split that follows is stated as chosen.** _Why:_ the specialist's lines each answer several positions, so the same density there would flag far more positions than is plausible. The resulting 90.8% expected to price automatically is a property of this tender, and DATA.md says so. _Amended 2026-11-17:_ after the generator changes of M2 the figures are 5.2%, 7.6% and 1.0% of the three offers' lines, and 92.1% expected to price automatically. _Alt:_ tuning traps until a round number appears (a benchmark built to produce its own headline).
19. **The catalogue has 254 products, not the roughly 300 the plan named, and names were replaced after a search.** _Why:_ 254 is what the product families produce without padding. The contractor, the specialist supplier and the data brand first had names too close to real businesses and were renamed before the first commit. _Deviation from the plan._
20. **Design direction "Planblatt": the app is a drawing sheet on a drafting table.** _Why:_ the people this is for read plans all day, so the interface borrows from one: a title block for the tender, square-cornered sheets with crop marks over a drafting grid, condensed capitals for field labels, and a checker's marks for what needs a decision. Light is plan paper, dark is a blueprint, copper is the one accent. It also keeps the product from looking like every other dashboard. _Alt:_ a neutral card layout (the M0 shell, replaced), or the warm "command center" look of an earlier project (not this domain).
21. **Components are built by hand on the tokens; shadcn/ui is not used.** _Why:_ the direction in ADR-20 needs square sheets, ruled grids and lettered labels, and restyling a component library to that costs more than the few primitives the app needs. _Amends ADR-14,_ which deferred shadcn/ui to M3. _Alt:_ shadcn/ui with its variables mapped onto the tokens.
22. **Status colours are validated, and blue sits between green and red.** _Why:_ approved (green), settled by the system (blue) and open (red) appear side by side in one bar. In that order every neighbouring pair passes the colour-blindness check of the dataviz validator against both sheet colours; green beside red does not. _Alt:_ green next to red with labels as the only safeguard.
23. **An independent audit closes every milestone.** _Why:_ the builder's own gate report cannot see its own blind spots. A fresh agent with no part in the work re-runs the gate in a clean checkout, recounts every number in the docs, checks the non-negotiables by search, and ranks what to tighten. High-severity findings are fixed before the gate is reported; the rest are listed in HANDOVER. _Alt:_ self-review only.
24. **The model call path uses `messages.create` and reads the answer itself.** _Why:_ found by the first audit. The SDK's `messages.parse` raises when the text does not fit the schema, which is what a response cut off at `max_tokens` looks like, and the raise skipped the ledger write for a billed call. `readStructured` turns every outcome into a value, the ledger row is written first, and a role can no longer name a model without a price. _Alt:_ catching the SDK's error (the usage is gone by then).
25. **Deviations the first audit found, logged after the fact.** M1 was built before the M0 gate closed, because the provider key arrived later and M1 needs no model. Ledger rows had no run id until the audit; they have one now. Pack units appear only on trapped lines, against the plan's call for messy clean lines; that is the first M2 task. The catalogue has 29 groups where the plan spoke of about 12 classes. `pnpm demo:reset` does not exist yet and arrives with replay mode.
26. **Design direction "Schaltplan" replaces "Planblatt".** _Why:_ the owner judged the drawing-sheet interface plain and crowded. The new one takes its form from what an electrician reads and builds: the tender is drawn as a single-line diagram (offers feed a busbar, titles go out as feeders), surfaces are modules on a mounting plate, status is shown by pilot lamps, and copper marks only what is energised or is the next thing to do. One view holds one headline, one sentence and one action; detail opens on request. One sequence of motion switches the diagram on; all other motion answers an action. _Supersedes ADR-20;_ ADR-21 (built by hand, no component library) stands. _Alt:_ polishing the sheet layout (it would have stayed a page of ruled boxes).
27. **The interface is built alongside the pipeline, not after it.** _Why:_ the owner asked for it side by side, and a flag is easier to judge on screen than in a JSON file. _Deviation from the plan,_ which put the whole product surface in M3.
28. **The list of positions is TanStack Virtual with hand-built rows, not TanStack Table.** _Why:_ it is one column of rows under headings, not a grid with sortable columns. _Deviation from the plan,_ which named TanStack Table; the review queue may still use it.
29. **Runtime dependencies added to the web app:** `motion` (layout and sequence animation), `@number-flow/react` (counting figures), `pdfjs-dist` (the source page), `@tanstack/react-virtual`, `lucide-react`, and Archivo and IBM Plex Mono through Fontsource. _Why:_ each replaces code that would otherwise be written by hand and tested less. pdf.js is loaded on first use and stays out of the first page's bundle.
30. **A behaviour probe and a contrast test join the gate.** _Why:_ the second audit found `pnpm shots` passing with six defects live: a list of 1,170 Tab stops in front of the numbers, a crash on a hand-typed search value, a price per ring of cable labelled per metre, the palette reopening on Enter. A screenshot cannot see any of them. `pnpm probe:ui` drives the app and checks them; `tokens.test.ts` checks the contrast of every colour pair in use, which also makes ADR-22 re-verifiable. _Alt:_ more screenshots.
31. **While a source is open, the list gives its room to the document.** _Why:_ a list, a position and a legible page do not fit side by side at 1440 px; in the earlier three-column layout the table text of a PDF was 4 to 5 px tall. Now position and document share the screen equally, the page is never drawn narrower than 640 px, and it opens scrolled to the mark. From 1800 px the list stays. J and K still step through the list while it is away. _Alt:_ zoom and pan inside a narrow pane, or a modal over the position (which hides the number that was clicked).
32. **The ground truth follows one rule: a position needs a person exactly when its cheapest offer is not a clean one.** _Why:_ the first audit found the old expectations disputable (a flagged offer beside a cheaper clean one still counted as a review). A trapped offer that is dearer than a clean one changes nothing about the price in the bid, so it is noted and nobody is asked; one that is cheaper, has no price per unit, or stands alone is a decision. The rule is the same in the generator's truth and in the pipeline's `decide`, written twice, and it is what "euros at stake" is computed from. _Alt:_ review whenever any offer carries a trap (more reviews, most of them with nothing to decide).
33. **A line that names no position is attributed by its quantity.** _Why:_ suppliers quote bulk material and luminaires by article, with the quantities of all positions added up. So the quantity says what the line was quoted against: it prunes a variant the text could not tell apart, completes a group the reading left a gap in, and reveals an article quoted in place of another. Positions with the same short text stand or fall together, and a difference found by arithmetic is never overruled. _Known limit:_ variants that share a short text (the same downlight in IP 20 and IP 44) can defeat it; the unseen tender shows that. _Alt:_ trusting the model's verdict per position (it is not the same every time for the same article).
34. **The model call path is split so it can be tested, and calls are recorded per batch.** _Why:_ the second audit found that a provider error was thrown, which in a batch of side-by-side calls would have lost the calls beside it, and that nothing tested the path. `llm/call.ts` returns every outcome as a value and is tested with a stand-in for the SDK; the runtime records a batch's calls in the transaction that stores their results, which also ends the contention on the day's total. _Alt:_ a try/catch around each call in the runtime (the path would still be untested).
35. **Equal questions share an answer, kept by a hash of what was asked.** _Why:_ the same article is asked for on seven floors. The hash covers the prompt version, the model and everything the model is shown, with lines numbered by their place in the list, so it does not depend on which position asks. A full run needs 880 calls instead of 1,170, a second run none, and a change to a check can be tried on the stored answers for nothing (`pnpm bench:replay`). _Alt:_ a call per position (a third more cost, and no replay).
36. **Search results are gated by how well their line fits elsewhere.** _Why:_ a text search returns its three best lines per supplier for every position, most of them for something else. A line fits the positions it was written for far better than the ones it shares a word with, so a result counts only if it scores half of what its line reaches for any position. On the demo tender that keeps every true offer and drops two thirds of the rest. _Disclosed:_ the depth and the share were set by measuring them on this tender. _Alt:_ a word-overlap gate (it loses offers written in shorthand: `CEE-Stdo.` shares no word with `CEE-Steckdose`).
37. **The prompt and the checks were changed after the first run, and the first run is kept.** _Why:_ the first full run was 99.8% right about what it priced by itself but raised 168 reviews where 101 were expected. The causes were a check of ours overruling the model wrongly, a generator bug the model exposed, and uneven answers for the same article ([DATA](DATA.md#what-changed-after-the-first-run-and-why-the-demo-tenders-score-is-not-the-headline)). The first run's results stay in `bench/results/baseline/`. _Alt:_ reporting only the final numbers.
38. **The headline number comes from a tender the pipeline had not seen.** _Why:_ everything in ADR-37 was done while looking at the demo tender's ground truth, so its perfect score proves little. `pnpm bench:heldout` generates a tender from another seed, runs it once and scores it, with nothing changed in between: 99.4% precision on what it prices by itself, 57 of 60 traps, 93.3% of expected reviews found. _Limit:_ unseen in its numbers, not in its language; it comes from the same generator. _Alt:_ a train and test split of one tender (the positions of a kind repeat across floors, so the halves would leak).
39. **Runs are started from the command line, not from the interface.** _Why:_ a run costs money, and until the access code and replay mode exist (M3) a public button would be an open tap. The interface shows the newest run live. _Deviation from the plan,_ which had the summary bar start runs.
40. **Labor is not priced in M2.** _Why:_ mapping a position to an entry of the labor time table is a matching task of its own, and the gate for M2 is about material. A run reports material value and what is at stake in it. _Deviation from the plan,_ which listed "pricing (material + labor + surcharge)" under M2; labor and the copper surcharge are M3.
41. **The escalation model stays off, and B4 is not run.** _Why:_ on the unseen tender the misses are a limit of attributing by quantity that a perfect reader shares, not of the reading. A larger model would not fix them, so there is nothing yet for it to earn. _Alt:_ running B4 anyway (about ten times the cost per call for a comparison whose answer is known).
42. **Design direction "Weidenufer" replaces "Schaltplan".** _Why:_ the owner turned the single-line diagram down as well and asked for more sophistication and no slop. The second audit agreed about the workspace: a standard list and detail with a tinted alert box. The new direction takes its picture from what the tender is for instead of from the trade's tools: the building itself, seen across the river at night, with one window per position, lit when priced and red when it needs a person, and mirrored in the water, which is the Spiegel in the name. A position is laid out as the estimator's own comparison sheet, suppliers side by side. Night is the default theme and day a stored choice. Type is Jost for what is said large and Archivo for what is read. _Supersedes ADR-26 and ADR-22:_ the green, blue, red bar is gone; lit and red windows are checked for contrast against the wall and each other in `tokens.test.ts`. ADR-21 (built by hand) stands. _Alt:_ refining the diagram (two rejections say the idea, not its polish, was the problem).
43. **A position's storey is read from its section name at load time and stored on the tender.** _Why:_ the building needs to know, for 1,170 positions, which storey each is on, before any list of positions has loaded. One character per position costs about a kilobyte and keeps the overview's first paint independent of the list. Reading "Unterverteilung 2. Obergeschoss" is pure code in `packages/core`, tested, and a tender that names no storeys is drawn as plain rows. _Alt:_ working it out in the browser from the full list (280 kB before the picture can be drawn).
44. **Work goes through feature branches and pull requests.** _Why:_ the owner asked for it after M2 had been committed straight to `main`. One branch per task, CI on the pull request, and the merge is the owner's. _Amends_ the working agreement of small commits per gate, which stands within a branch.
45. **A line is also put to the model for the positions whose quantities add up to its own.** _Why:_ the audit of M2 found the search fitted to the demo tender. A by-article line quoted in place of the article asked for reads like its own product, so a text search does not lead from the positions to it; on six other tenders 6 to 11 true offers never reached a reader, and a perfect reader agreed with the truth on none. The quantity is the total of exactly the positions the line was quoted for, so it is used as a second way in, for a quantity that fits at most two kinds of position. After it, no true offer is lost on fifteen tenders, and a perfect reader agrees on every position of six out of eight tenders nobody had looked at. _Amends ADR-36,_ whose "keeps every true offer" held for the demo tender only, and _ADR-33 and ADR-41,_ which blamed luminaire variants for misses that were this. _Alt:_ a deeper text search (the line ranked seventh or eighth, and depth costs a call's worth of reading on every position).
46. **The headline number is from a tender generated after a fix, and both unseen runs are kept.** _Why:_ ADR-38 made seed 119 the tender to judge by. Fixing the search (ADR-45) changes what the model is asked, so its old numbers no longer describe the pipeline, and its failures had been read while fixing. Seed 501 was generated, run once and scored: everything priced without a person is rightly so, every expected review is found, 94.7% of raised reviews belong, 58 of 60 traps, and seven positions priced at a valid offer that is not the cheapest (1,417 €). `pnpm bench:seeds` and a test over three audited seeds keep the model-free part honest on every change. _Limit:_ both unseen runs took part of their answers from the cache, and seed 501 has now been read for its write-up, so the next change needs another seed. _Alt:_ re-running seed 119 (it had been looked at).
47. **What the M2 audit found and what was done with it.** Verdict: "on plan, with gaps". Fixed here: the search (ADR-45), the wrong cause in the write-up of the unseen tender, the unbacked "880 calls, $0.38", the statements that nothing the model writes is shown as a number and that a failed call always leads to a review, the scope of B3, stale lines in the README and ARCHITECTURE, and a model id outside the registry. Not fixed, listed in HANDOVER §5 for M3: quotes checked by substring, attribution that leans on how the generator writes quantities, ledger rows written at the end of a batch and no watchdog for a dead step, a cache key that does not cover the prompt text, edge cases where `decide` and the ground truth differ, and scoring that does not look at the reason of a review. _Deviation logged after the fact:_ the interface was being rebuilt in the working copy while the audit ran, so the audit served the audited commit itself.
48. **Four rules replace what the second audit showed to be fitted, and a sweep over fresh seeds is the measure.** _Why:_ the audit of ADR-45 ran 136 tenders nobody had named: the search still lost true offers on 21 and a perfect reader priced positions that needed a person on 20. ADR-45 had been reported with eight tenders as evidence. Four causes were found on the audit's seeds: one short text for two things (a kind of position is now its short text plus the measures and codes its long text states); a by-article line that covers only some storeys (a quantity that is the total of some of the matching positions is accounted for); two substitutions on one supplier (a by-article line is a supplier's answer to a position only if its quantity is the total of what it matches); and a price measured against another product (only offers of the same product are compared). A quantity that fits many kinds keeps the kinds the line reads most like. On 200 seeds never looked at, with nothing changed afterwards, a perfect reader agrees with the ground truth on every position of 198, loses a true offer on 4, prices a position that needed a person on 2 and misses a trap on 8. _Amends ADR-45,_ whose "no true offer is lost" held for sixteen named seeds. _Cost:_ the second rule weakens the quantity check on by-article lines that match many positions. _Alt:_ subset sums in the search as the audit proposed (nearly every quantity is the total of some positions of a large kind, so it would have shown most lines to most kinds).
49. **The headline moves to seed 502, and a number about tenders is quoted as a rate.** _Why:_ ADR-48 changes the checks again, so seed 501's run no longer describes the pipeline. Seed 502 was generated, run once from a clean tree and scored: everything priced without a person is rightly so, 96 of 96 expected reviews, 98.0% of raised reviews belong, 60 of 60 traps, one position 170 € too high. One tender is one draw, so the README quotes the sweep beside it. _Limit:_ 353 of its 856 distinct answers came from earlier tenders through the cache, and seed 502 has now been read for its write-up.
50. **What the second audit found and what was done with it.** Verdict: "On plan, with gaps. The gate re-runs green and every table figure recounts, but the high finding is narrowed, not closed." Fixed here: the checks (ADR-48); the generator failing on 14 seeds in 150; a test that could not have caught the regression; the claims "that finding is fixed", "six of eight" and "all on luminaires"; the cache figure; the altered-line count; storey words matched inside other words; the reflection appearing before the lights; bays without names; a front drawn at 8 px between 1024 and 1280 px; the costliest list repeating one article per storey; columns that did not stack beside a document at 1440 px. Not fixed, listed in HANDOVER §5: the drawing of a measure shows values the model wrote; the lower half of the overview and the positions list are ordinary; both shapes of the building are mounted; small touch targets on a phone; the day theme loses the picture of lit windows; nothing can be decided yet. _Logged after the fact:_ the seed-501 result files were written from a tree with uncommitted changes; seed 502's were not.
51. **A rate over tenders is quoted pooled, with every range that has been run, and a claim about the model is withdrawn.** _Why:_ a third audit of the pipeline reproduced every figure of ADR-48 and found no fitting to the seeds the rules were built on, but its own 597 tenders came to 97.5% where the one range quoted had come to 99%: that range was the most favourable of five. The docs now quote 780 of 797 (97.9%), with a position that needed a person priced on 2.0% of tenders and a trap missed on 4.3%, and name the case behind most of it, a tie between two totals, which is not fixed. The README had said the errors on the unseen tender were not misreadings a larger model would fix; all three start in the model's answer, so that reason for not running B4 (ADR-41) is withdrawn and B4 on those positions is the cheapest open experiment. The audit rated nothing high; what it rated medium (the kind key fitted to the generator's wording, the weakened quantity check, the tie) is listed in HANDOVER §5. _Logged after the fact:_ the demo tender's result files were written from a tree with an uncommitted change (`df3b1c1-dirty`), as seed 501's had been. The interface behaviours added after the fourth audit now have probe checks.
52. **The grid stays; a house, a sky and a sea are built around it, and the day theme keeps the picture.** _Why:_ the owner liked the idea and asked for it to look like a building in front of water under a night or a day sky, without touching the grid, and for the auditor's criticisms to be answered. The auditor had said that slivers with no roof, sky or ground read as a status matrix, that by day a priced window was dark so the picture was gone, and that the lower half was two bar lists beside a table. Now the front has a roof with a set-back storey, plant, a mast and its name; the sky has stars and a moon or clouds and a sun; the far shore runs along the horizon; the quay and the sea lie in front. By day the wall is dark slate and the glass shows the sky, so the priced window is the bright one in both themes. The reasons moved out of a bar list into the key under the picture, where pointing at a reason or a title picks its windows out on the house. _Amends ADR-42._ _Not done:_ the plinth's groups still do not stand under their bays (the grid was not to be touched), and the positions list is still a list.
53. **English is complete: trade terms, figures, and the tender's own structure.** _Why:_ the owner found the English half-translated. The interface kept German domain words on purpose (ADR-42 and before), which left an English reader with "Leistungsverzeichnis", German figures, and every section, storey and item in German. Now the English copy says bill of quantities and item; figures, dates and units follow the language; and a glossary of trade terms renders sections, storeys, attribute names and all 239 distinct item names of the demo tender, tested for German left over. The tender's wording stays visible under an item's English name, and long texts and suppliers' lines are never translated, because they are what was written. _Limit:_ the glossary is a list of phrases, not a translator; a real tender would bring words it does not have, and those are shown as they are. _Alt:_ a model translating on the fly (a cost on every page, and a second thing that can be wrong about what a document says).
54. **A position that needs a person can be decided, and the decision belongs to the browser that made it.** _Why:_ the fourth audit's first risk was that nothing could be decided: a red window could be opened and read and never go out, though the PRD has the estimator decide from the keyboard. Now the estimator takes one of the offers as it stands (keys 1 to 3 for the three columns, or a button), or types a price of their own, and takes it back with U. The price of an offer is read on the server from what the run stored, never from the browser; a typed price is a number a person originated, which is allowed. The run's results are left as they are and shared; what a person decided is laid over them in the browser (`lib/decisions.ts`), so the window turns from red to lit, the position leaves the queue and the sums follow. The demo has no accounts, so a decision is stored under a random id the browser keeps, and two visitors do not see each other's. _Limit:_ nothing stops a script from making up ids and writing rows; a rate limit belongs with the public deployment (M4). A decision names an offer of the newest finished run and keeps its price if a later run reads the offers differently. _Alt:_ decisions shared by everyone (the first visitor would decide the demo for all the others), or kept in the browser only (nothing to show that the backend is in the loop).
