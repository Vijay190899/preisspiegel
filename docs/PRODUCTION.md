# Production readiness

Before the first deployment, the product was held against what a production web product is expected to have. This page lists, area by area, where it stood, what was done (ADR-63 to 66), and what is left on purpose. It was written on 2026-11-18, at the end of M3.

The yardstick is a small B2B product with real users and no on-call team. It is not a bank. A demo has no accounts, so anything that needs an identity is judged by what a visitor's browser can do.

Unchanged, and already at the bar: strict TypeScript with no `any` and no ignored errors; every Convex argument validated; the typed environment; a single path for model calls, with a ledger and budgets; secrets only in the deployment's environment; CI that lints, formats, type-checks six projects, tests and builds; a first load of about 240 KB of scripts and styles gzipped (fonts on top), with the PDF reader loaded only when a document opens.

## Left on purpose

- **Accounts.** The demo has none, so decisions belong to a browser's random id. A product would sign people in (Convex Auth or an identity provider) and key every limit to the user. The limits here bound what made-up ids can do overall.
- **Script nonces in the CSP.** Scripts are allowed `'unsafe-inline'` because the server-rendered page hydrates from inline scripts and sets the theme before paint. A per-request nonce would close that. It needs a request middleware and the router's nonce option, and it is the next step for the headers (ADR-64). Everything else in the policy is held to this origin and the Convex deployment.
- **Error tracking.** Failures are in the Convex logs, in each run's event log and in the browser console. A product would send them to a tracker such as Sentry, which needs an account, and route alerts to someone.
- **End-to-end tests in CI.** The behaviour and accessibility probes need a deployment with a finished run and its stored answers, so they run locally at every gate rather than in CI. CI does cover the API layer with `convex-test`.
- **The first load of the positions list** sends every position (about 280 KB) so the list can be searched in the browser. A larger tender would page it from the server.
- **Both shapes of the building are in the page** (2,340 window elements) and CSS picks one. Mounting one would save main-thread time on a phone, but it changes the grid's markup, which is left as it is (ADR-52).
- **What M4 and after would add** (from the eighth audit): separate environments, so a preview build does not write to the production deployment; uptime checks and an alert; deploying the Convex functions from CI, with a backup and restore drill; a bound on query bandwidth, which Convex bills; an Impressum and a privacy note for a German public site, which need the owner's details; CSP reporting; and a load test.
- **One high advisory** (`picomatch`, used by TanStack's route generator at build time) has no patched release yet. It does not ship to the browser or the server. It is why CI gates on critical rather than high.
